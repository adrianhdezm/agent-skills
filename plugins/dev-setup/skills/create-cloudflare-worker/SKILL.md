# Create Cloudflare Worker

Creates a single-Worker TypeScript project with this shape:

- **Hono on Workers, built by Vite.** `@cloudflare/vite-plugin` runs `vite dev` inside workerd and builds to `dist/`;
  `wrangler deploy` ships the build. The entry point is `src/app.ts`, which exports the Hono app as the default.
- **Wrangler owns the runtime types.** `wrangler types` writes `worker-configuration.d.ts` from `wrangler.jsonc`; it is
  committed and regenerated by `typecheck`. No `@cloudflare/workers-types`, no DOM lib.
- **pnpm**, with TypeScript pinned exactly on the 6 line (typescript-eslint supports only `<6.1`) and caret ranges for
  the rest.
- **Prettier formats, ESLint judges.** ESLint runs with type information (`recommendedTypeChecked`); its formatting
  rules are switched off.
- **Vitest through `@cloudflare/vitest-plugin`**, so tests run inside workerd against the real Worker. Tests live in
  `tests/`, one `*.test.ts` per module.
- **Four checks, all required to pass:** `typecheck`, `lint`, `test`, `build`.

There are no templates and no `pnpm create cloudflare`: its templates bring React Router, DOM and `composite` settings
that break a plain Worker. The tools' own CLIs create what they can (`git init`, `pnpm init`, `pnpm pkg set`,
`pnpm add`, `pnpm approve-builds`, `wrangler types`); every other file is written from the specification in
[references/tooling.md](references/tooling.md).

**Done means:** the four checks pass, nothing was emitted into the tree, and every item on the
[Review Checklist](#review-checklist) holds.

## What gets created

```
my-worker/
├── .gitignore
├── .prettierignore
├── .prettierrc
├── eslint.config.js
├── package.json
├── pnpm-lock.yaml
├── pnpm-workspace.yaml        # pnpm settings only (allowBuilds); not a workspace
├── tsconfig.json              # solution file: only references the three below
├── tsconfig.cloudflare.json   # src/, runs in workerd
├── tsconfig.node.json         # vite.config.ts, vitest.config.ts: run in Node
├── tsconfig.test.json         # src/ + tests/, workerd plus the test runtime types
├── vite.config.ts
├── vitest.config.ts
├── worker-configuration.d.ts  # generated by `wrangler types`; committed
├── wrangler.jsonc
├── src/
│   └── app.ts                 # the Hono app, default export
└── tests/
    └── app.test.ts            # one ….test.ts per module in src/, same name
```

## Process

Copy this checklist and tick it off:

```
- [ ] 1. Toolchain checked
- [ ] 2. Directory, git and package.json created
- [ ] 3. Dependencies installed, TypeScript pinned, builds approved
- [ ] 4. Config files written from the spec, runtime types generated
- [ ] 5. App and its test written
- [ ] 6. Formatted and checked
```

Once the description is settled, run every step to the end without asking. Stop only when the toolchain is missing,
the target already holds a `package.json`, or a check still fails after you have found its cause.

1. **Check the toolchain.** `node --version` must be 24 or newer, `pnpm --version` 11 or newer (`allowBuilds` is a pnpm
   11 setting). Use pnpm for everything, never npm. Stop if the target directory already holds a `package.json`: follow
   [Adding the tooling to an existing project](#adding-the-tooling-to-an-existing-project) instead.

2. **Create the directory, git and `package.json`.** Ask for a one-sentence description if the user has not given one.

   ```sh
   mkdir -p my-worker/src my-worker/tests && cd my-worker
   git init -q
   pnpm init --bare --no-init-package-manager
   pnpm pkg set name=my-worker version=0.1.0 description="One sentence on what it does." \
     type=module engines.node=">=24" \
     scripts.cf-typegen="wrangler types" \
     scripts.typecheck="pnpm run cf-typegen && tsc -b" \
     scripts.lint="eslint ." \
     "scripts['lint:fix']=eslint . --fix" \
     scripts.test="vitest run" \
     scripts.dev="vite dev" \
     scripts.build="vite build" \
     scripts.preview="pnpm run build && vite preview" \
     scripts.deploy="pnpm run build && wrangler deploy" \
     scripts.format="prettier --write . --cache" \
     "scripts['format:check']=prettier --check . --cache"
   pnpm pkg set private=true --json
   ```

   `private` is set on its own line because only `--json` stores it as a boolean. A script name with a `:` needs the
   quoted bracket form, `"scripts['lint:fix']=…"`; `scripts.lint:fix=…` is rejected as an invalid property path.

3. **Install the dependencies**, pin TypeScript to the exact version installed, and approve the two install scripts,
   which writes `pnpm-workspace.yaml`:

   ```sh
   pnpm add hono
   pnpm add -D typescript@6 @types/node@24 wrangler vite @cloudflare/vite-plugin vitest @cloudflare/vitest-plugin \
     eslint @eslint/js typescript-eslint eslint-config-prettier prettier
   pnpm add -D -E typescript@"$(node -p "require('typescript/package.json').version")"
   pnpm approve-builds esbuild workerd
   ```

   Before installing, check the peer ranges have not moved (see [Versions](references/tooling.md#versions)):
   `pnpm view typescript-eslint peerDependencies` for the TypeScript ceiling, and
   `pnpm view @cloudflare/vitest-plugin peerDependencies` for the Vitest major. `@types/node` follows the local Node
   major.

4. **Write the config files** from [references/tooling.md](references/tooling.md): `wrangler.jsonc`, `vite.config.ts`,
   `vitest.config.ts`, the four tsconfig files, `eslint.config.js`, `.prettierrc`, `.prettierignore`, `.gitignore`.
   Every value the spec gives is required as given. Set `compatibility_date` to today's date in UTC, `date -u +%F`; a
   local date ahead of UTC is rejected as a future date. Then generate the runtime types:

   ```sh
   pnpm cf-typegen
   ```

5. **Write the app and its test.** Use the routes the user asked for; if there are none yet, write a starter
   `src/app.ts` with `GET /` returning `c.text('Hello Cloudflare Workers!')` and `export default app`, plus
   `tests/app.test.ts` that calls it through `exports.default.fetch()` from `cloudflare:workers`, in Arrange / Act /
   Assert. The full starter test is in [references/tooling.md](references/tooling.md#the-starter-test). Vitest fails
   when it finds no test files, so the app and its test always come together.

6. **Format and run the checks.**

   ```sh
   pnpm format
   pnpm typecheck && pnpm lint && pnpm test && pnpm build
   ```

   All four pass. Then confirm what the checks miss: `private` is `true` (a boolean), `typescript` has an exact version
   with no `^`, and the repository root holds no emitted `*.js`, `*.d.ts` or `*.tsbuildinfo` next to the sources.

## End of the run

End with three headings: **Blocked on me** (a check that still fails), **Changed** (the project path and what was
created) and **Found** (anything that differed from the spec, such as a moved peer range). When another skill called
this one, such as `design-solution`, hand these back to it instead.

## Rules the tooling enforces

These bite first when writing code in the project:

- **No DOM.** The Worker's globals come from `worker-configuration.d.ts` alone. Adding `"DOM"` to `lib` produces dozens
  of conflicting declarations.
- **Bindings are typed by Wrangler.** After adding a binding, variable or secret to `wrangler.jsonc`, run
  `pnpm cf-typegen` (or `pnpm typecheck`, which runs it) and use `new Hono<{ Bindings: Env }>()`. Never hand-write the
  `Env` interface.
- **`import type` for types** (`verbatimModuleSyntax`); inline style, `import { type X, y }`, is what ESLint fixes to.
- **No `enum`, `namespace` or parameter properties** (`erasableSyntaxOnly`). Use `as const` objects and unions.
- **`array[0]` is `T | undefined`** (`noUncheckedIndexedAccess`); handle it.
- **`_` prefix** marks an intentionally unused parameter or destructured value.
- **Floating promises are errors.** In a Worker an un-awaited promise is cut off when the response returns; `await` it
  or hand it to `c.executionCtx.waitUntil()`.
- **Tests reach the Worker through `cloudflare:workers`** (`exports`, `env`). `SELF` and `env` from `cloudflare:test`
  are deprecated.
- **Every new config file** goes into the `include` of `tsconfig.node.json`, or ESLint reports it as belonging to no
  project.
- **Secrets** go in `.dev.vars` locally (git-ignored) and `wrangler secret put` in production, never in
  `wrangler.jsonc`.

## Adding the tooling to an existing project

Skip `pnpm init`, and do not overwrite what is there:

1. Set the scripts from step 2 with `pnpm pkg set`. Check with the user before replacing a script that already exists
   under the same name.
2. Install the dependencies as in step 3. Move `typescript` to `devDependencies` if it sits in `dependencies`.
3. Write each config file the project lacks. Where one exists, merge the spec's values into it and say what changed.
   Configs copied from a Cloudflare or React Router template usually need: `DOM` and `vite/client` removed, `composite`
   replaced by `noEmit` plus `tsBuildInfoFile`, `include` pointed at `src/` instead of `app/` and `workers/`, and `jsx`,
   `paths`, `rootDirs` and `esModuleInterop` dropped.
4. Delete any `*.js`, `*.d.ts` and `*.tsbuildinfo` that an earlier `tsc -b` emitted next to the sources.
5. Run `pnpm format`, then the four checks, and fix what they report.
