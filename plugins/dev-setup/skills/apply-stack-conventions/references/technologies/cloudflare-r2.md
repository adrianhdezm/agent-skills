# Cloudflare R2

R2 as the object store on Cloudflare Workers: a bucket bound to the Worker, its type generated by Wrangler, reached
through the file service on the app's context.

**Realises:** [File storage](../architecture/file-storage.md)

## Use it like this

- **The bucket is created by Wrangler and bound in one step**:
  `pnpm wrangler r2 bucket create <name> --binding=APP_FILES --update-config` writes the binding into `wrangler.jsonc`,
  merged with what is there. The name is the user's, or the project's in hyphen case with `-files`.
- **The binding is typed by `wrangler types`**: `APP_FILES: R2Bucket` appears in `Env` after `pnpm cf-typegen`.
- **The file service takes the bucket from the bindings**, built inside the request handler with the request's database
  client: `new FilesService(db, c.env.APP_FILES)`.
- **Bytes go in as an `ArrayBuffer` (or a stream or a string)**, with the content type in `httpMetadata`.

## Required values

| What             | Value                                                                 |
| ---------------- | --------------------------------------------------------------------- |
| `wrangler.jsonc` | `"r2_buckets": [{ "binding": "APP_FILES", "bucket_name": "<name>" }]` |
| binding name     | `APP_FILES`                                                           |

## Pitfalls

- **`r2_bucket` (singular) is silently ignored**: the key is `r2_buckets`.
- **`put()` takes a `ReadableStream`, `ArrayBuffer` or string**, not a `File` or `Blob`: pass `await file.arrayBuffer()`.
- **Bucket names are unique across every Cloudflare account**: a taken name fails the create.
- **Rewriting `wrangler.jsonc` by hand** drops other bindings: merge.

## Conventions

- **The bucket is bound as `APP_FILES` under `r2_buckets`**; after a binding change, `pnpm cf-typegen` and commit
  `worker-configuration.d.ts`.
- **Only the file service touches the bucket**, built per request from `c.env.APP_FILES`.
